# heige-claude-video 视频生产系统

把一句选题或一份口播稿，做成一条 16:9、1920×1080、30fps 的原理动画科普视频。方法论见 `references/`，动手前先读对应篇章。

## 六条硬规则（每条都是实测踩坑换来的）

1. **音频是时钟。** 音频定版后才建工程、才做字幕和动画；所有关键动作卡在词级时间戳上，误差不超过 0.1 秒。
2. **获得物先行。** 每条视频必须有获得物（免费开源项目、可照做的清单、可核实的数字），开头 10 秒讲明。没有获得物的选题退回选题阶段。
3. **只听也懂。** 屏幕上展示的东西（提示词、清单、对话原文、规则）口播里都要说出来；引用 AI 或别人的话要交代是谁说的；前提先交代再用。写完闭眼听一遍。
4. **只沉淀流程，不沉淀画面。** 每集画面按本集内容从零设计，不照搬上一集的布景、配色和组件；上一集只用来看写法（怎么卡字、怎么进出场、怎么拆组件）。
5. **不用音效。** 成片只有人声和背景音乐两层。原卡音效的位置（揭晓、数字、对比、警告、转场）用视觉强调动效替代，做法见 animation-techniques.md。
6. **不看图不交付。** 拼图、单帧、花屏扫描、碎片帧检测，机器自查加人工看图至少两轮；只写真实发生的事，不虚构产物。

## 流程总览

```text
选题（过五关）→ 口播稿（writing-rules.md）
→ 建工程（一个视频一个文件夹）
→ 逐句配音 → whisper 回读挑最准 → 大模型逐句复核 → 词级时间轴
→ 分镜（先写一页分镜再写代码）
→ 画面设计（animation-system.md + animation-techniques.md）
→ 混音（两层声音，响度定标准）→ 渲染
→ 质检自查（qa-and-delivery.md）→ 三张封面 → 发布文案
→ 合规扫描（compliance.md）→ 交给用户发布（不自动发布）
```

## 分工边界

- **本 skill 负责**：方法、规范、自查清单、每一步的成功标准。
- **渲染管线由用户环境决定**：推荐 Remotion（逐帧确定性渲染天然匹配「音频是时钟」），HTML Canvas、After Effects 等也可以，规范与管线无关。
- **配音由用户环境决定**：克隆声音、TTS 服务、真人录音都可以；本 skill 规定的是回读、挑选、时间轴的做法，不是具体某个声音。
- **发布永远不自动执行**：出完片、封面和发布文案后交还用户。

## 开始一个新视频前

1. 问清楚或从稿子判断：主题、时长、有没有获得物、目标观众。
2. 读 writing-rules.md 检查稿子（或从选题起稿）。
3. 读 production-pipeline.md 对应环节动手。
4. 每完成一个环节，核对该环节的成功标准再进入下一个。
