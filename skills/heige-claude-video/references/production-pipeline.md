# 出片全流程（production-pipeline）

一条视频从稿子到成片的完整路径。每个环节都有成功标准，核对通过才进下一个。

## 0. 工程结构：一个视频一个文件夹

```text
视频/<三位编号>-<短标题>/
├── 00-文案/          # 口播稿、事实来源
├── 工程/             # 渲染工程（推荐 Remotion）
├── 01-成片/          # 最终 mp4
├── 02-封面/          # 三张封面
├── 03-发布文案/      # 发布标题、封面短标题、各平台简介
├── 04-素材/          # 生图原图、截图、音乐和授权记录
└── README.md         # 状态卡：产出物表、当前状态、怎么重出
```

原则：素材和产出全部进本期文件夹；只把真实存在、核对过的文件算交付。

稿子用结构化格式（推荐 script.json），按场景分句：

```json
[
  {"scene": "hook",    "lines": ["……", "……"]},
  {"scene": "mechanism", "lines": ["……"]},
  {"scene": "sign",    "lines": ["固定签名句"]}
]
```

一句一行，一行 3 秒左右最好念；场景名用英文小写，就是画面里的场景组件名；最后一句固定是签名场景。改了稿子必须重配对应句子、重跑时间轴，场景代码里的取字锚点要全局搜一遍。

## 1. 逐句配音

- 每句独立生成一个音频文件（全片从 00 编号），模型只加载一次，已有句子跳过，支持断点续跑和个别句重做。
- 每句可以出多个版本（换随机种子），后面靠回读打分挑。
- 句内停顿按语义处理：原稿标点处该断就断，不该断的地方断了要重生成或后期收紧。
- 数字加量词（「4 招」「3 个」）容易被 TTS 念出奇怪的停顿，写稿时就写汉字（「四招」「三个」），字幕里再程序替换回阿拉伯数字。

## 2. 回读核对，挑最准

对每句配音用 whisper 回读，和原稿对比打分（去标点、小写、同音归一后算相似度）：

- 低于阈值（建议 0.93）的句子：换种子重新生成几版，全部打分挑最高；同分留原版。
- 通用同音归一表：他她→它、得地→的、再→在；本集专有听错字追加「错字:正字」对。
- **回读分数会漏两类真问题**，所以要再做一层大模型逐句复核（large 级模型单独转写每句）：
  1. 整段几乎没念出来，回读照样给高分；
  2. 系统性读错（某个字反复念错），换 3 个种子都不准的就是，改写法而不是碰运气。
- 复核时不要带含关键词的提示词，会掩盖句首吞字。
- 字准不等于自然：对全片跑句内停顿检测，开场几句逗号不换气的补 0.18 秒左右的停顿。
- 成功标准：全部句子字准过线，人工抽查无吞字、无奇怪停顿。

## 3. 词级时间轴

- 每句裁掉首尾静音（前留 25ms、后留 50ms），按固定节奏排布：片头留白、同场景句间 0.32 秒、换场景 1.0 秒、片尾留白，拼成整条旁白。
- whisper 的逐词时间戳按字均分、和稿子逐字对齐，对不上的字线性插值。**画面卡字用的是稿子原文**，不受回读听错影响。
- 词表不含标点和百分号：取字时间时「57%」「，」这类锚点找不到会静默退回句首，时间轴生成后跑一遍锚点修正，自动修掉带标点空格的锚点。
- 成功标准：时间轴的句数、场景顺序和稿子一致；总时长就是成片时长。

## 4. 分镜：先写一页，再写代码

改分镜几分钟，改动画要重渲，所以分镜阶段把问题想清楚。一页分镜包含：

- 一句话立意：主角想什么，但什么，于是什么。
- 世界、贯穿道具、颜色弧线（开头什么色、中段什么色、结尾什么色，红色只在风险出现）、首尾押韵（开头结尾同一景别同一状态对比）。
- 每个镜头：口播是哪句、观众每句看到什么变化、卡在哪个字、反应晚于起因 0.15 到 0.3 秒。
- 自审清单：每个镜头有事件吗？读点有没有叠？红色是不是只表示风险？

## 5. 画面设计

见 [animation-system.md](animation-system.md)（视觉系统和信息层）和 [animation-techniques.md](animation-techniques.md)（动效技法）。要点：

- 每集从零设计，先问自己：这期讲的机制，观众每一句该看到什么变化？
- 画面里数值是示意的要标「示意」；事实性说法单独审一遍（原理类内容常见错：把近似说成等式、把个例说成通则）。
- 事件类内容必须放官方原文卡：每一处「某某说」「报告写明」，画面上都要有官方原句截图卡，高光扫过的时间卡在口播念到这句的时候。

## 6. 混音：两层声音，响度定标准

- 成片只有两层：人声 + 背景音乐。**不用音效**，原卡音效的位置用视觉动效替代。
- 音乐用一首固定的授权曲循环（接缝做等功率交叉淡化，片头渐入、片尾渐出）；换曲要有人工确认的授权记录。
- 响度写死成统一标准，每集不改：人声目标约 -13.7 LUFS、真峰值 -2.0 dBTP、音乐比人声低约 14 dB。成品整体验在 -14.7 ± 0.6 LUFS。
- 混音前做去喷麦：送气爆破音在克隆声音里表现为低频孤立大摆幅，用高通加局部窄带高通处理，处理后残留摆幅要为 0。
- 成功标准：打印的响度和真峰值在标准内；逐句人声至少高过音乐 10 dB。

## 7. 渲染

- 推荐 Remotion（逐帧确定性）：场景顺序和时长全部从时间轴推导，不手写场景表；未登记的场景画面直接报红。
- 渲染完自动重封装音轨（部分编码器不写 AAC 前导采样，音轨会整体晚约 42 毫秒，重封装后归零）。
- 编码核对：1920×1080、30fps、h264 + aac，视频帧数 = ceil(总秒数 × 30)，ffmpeg 全片解码无报错。
- 已知坑：共享缓存会让抽帧渲出旧版本，抽帧发现画面和时间对不上先关缓存；渲染浏览器要用固定版本的 headless shell，新版本 Chrome 会随机把画面截成重复小块。

## 8. 封面和发布文案

- 三张封面各自构图（不是同一张裁三份）：3:4、4:3、16:9。标题文字程序排版，缩略图大小下可读，安全边距内无裁切。
- 发布文案分开保存：完整发布标题、封面短标题、各平台简介，互不混用。生成文案不等于代发。
