# 质检与交付（qa-and-delivery）

不看图不交付。每件自查工具证明的东西不一样，不能互相代替。

## 四道机器自查 + 人工看图

1. **拼图**：成片每句中点抽一帧，拼成网格图逐张看：读点对不对、字幕和画面有没有打架、有没有空场、有没有违禁色。至少两轮（第一轮找问题，改完再拼一次对比）。
2. **单帧**：拼图里可疑的地方出全分辨率 PNG 看细节：字号、裁切、元素穿插；关键卡点（揭晓、转场、签名盖章）逐个抽。
3. **花屏扫描**：渲染偶发「截图没画完」的单帧坏帧（字幕、进度条、整块区域缺失）。做法：逐帧缩成小图分块比对，找「某一块和前后两帧都差很多、前后两帧彼此很像」的候选；候选帧单独重渲后和成片同帧比 PSNR，低于 35 dB 才确认；确认后只补坏帧（单帧重渲替换），不整片重渲。设计内的单帧变化（数字滚动、闪烁）两边一致（44 dB 以上），自动排除。
4. **碎片帧检测**：新版渲染浏览器会随机把画面截成重复小块，且常常连坏两帧，单帧突变扫描会漏。做法：每帧做水平和垂直自移位比对，能抓到连续坏帧；有碎片就换固定版本的渲染浏览器重渲。
5. **成片回读**：对成片跑一遍语音识别和稿子对一遍，重点听场景交界和签名句。抽帧和扫描不等于听完，没人工听就不能写「已听」。

## 回归：全片逐帧 PSNR

改了模板或工程后，和基准片做**全片逐帧 PSNR**，不能只抽查改动的那一段（教训：同步命令覆盖了本期的场景文件，只抽查片尾没发现，正片被换成了占位画面）：

- 报平均、最低帧（帧号、秒数）、低于 35/30 dB 的帧数，低于 35 dB 的帧逐个目检确认原因。
- 同一份代码重渲的正常范围是平均 50 dB 上下；大面积掉到 20 到 30 dB 说明代码或字体真的变了。

## 编码核对

- ffprobe 核对：1920×1080、30fps、h264、aac，视频帧数 = ceil(总秒数 × 30)。
- ffmpeg 全片解码无报错。
- 成片音轨做重封装检查（部分编码器导致音轨整体晚约 42 毫秒的问题）。

## 交付物清单

| 交付物 | 要求 |
|---|---|
| 成片 mp4 | 01-成片/，文件名含 IP、标题、形式；核对字节数 |
| 三张封面 | 3:4、4:3、16:9 各自构图，缩略图可读 |
| 发布文案.md | 完整发布标题、封面短标题、各平台简介分开保存 |
| 状态卡 README | 产出物表、当前状态、怎么重出；只写真实发生的事 |
| 质检记录 | 拼图首轮和终轮、花屏扫描结果、回读结论 |

三处记录分开：用户认可、技术验收、公开发布，不从历史对话推断进度。

## 常见坑（每条都真实发生过）

- **缓存出旧画面**：改了源码抽帧却还是旧画面，先关渲染缓存，别怀疑时间轴。
- **字体回退**：某元素没显式指定字体时落到浏览器默认字体，行高漂移导致两台机器渲出的画面不同；给渲染根组件设默认字体。
- **原始大图花屏**：往工程里放几 MB 的原始 PNG，截图偶发没画完；图片按显示尺寸 2 到 3 倍准备。
- **同步覆盖**：用复制或同步命令改模板时覆盖了本期的场景文件；改完必须全片看，不能只抽查改动段。
- **取字锚点静默失败**：取字函数找不到子串时静默退回句首，画面不报错但卡点全错；找不到必须报错，出片前清零。
- **等待条件匹配到自己**：用「命令行里含某进程名」当等待条件，会匹配到等待命令自己，永远不结束；改成检查产物文件是否出现。
